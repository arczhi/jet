01 / The loop

一次请求，发生了什么？

它不是把聊天记录无限加长，而是每一步都从持久化状态中重新组装一个合适的工作窗口。

01

保存状态

用户请求、工具结果、计划节点都成为 SQLite 中的 chunk。

02

选择上下文

judge 判断哪些历史需要隐藏、备注、摘要或全文。

03

选择工具

所有工具都有简介，只有本步可能用到的工具获得完整 schema。

04

执行工作

worker LLM 流式输出；策略检查后才真正执行写入或命令。

05

验证结果

把目标、答案和证据交给验证器，失败时有限重试，绝不无限循环。

02 / RLCD

历史不会被压扁，
只是暂时换一种呈现。

普通摘要会覆盖旧信息。jet 保留原文，把“摘要”当成某一次请求的临时视图；下一步仍可以重新取回全文。

03 / Division of labor

三种角色，三种擅长。

把“判断”和“创造”拆开，才不会让昂贵的大模型处理每一个琐碎选择。

CHEAP + FREQUENT

Judge

做结构化判断：相关性、工具路由、计划门控、权限建议、完成验证。

EXPENSIVE + FOCUSED

Worker

读取精简后的上下文，写代码、调用工具、回答用户。只把成本花在真正的工作上。

DETERMINISTIC

Code

拥有阈值、预算、递归深度、权限规则、重复调用拒绝和停止条件。

04 / Safety boundary

模型可以建议，
不能偷偷放行。

对于写文件和执行命令，决策是单向收紧的。确定性规则永远先于模型意见。

① 确定性规则拦截 sudo、危险递归删除、远程内容直接 pipe 到 shell 等明确风险。
② Judge 安全意见发现规则没覆盖到的潜在泄漏、破坏或越权风险时，只能把结果收紧。
③ 人工确认Ask 模式下交给用户确认；没有 approver 时默认拒绝，失败关闭。
05 / Why it matters

创新不在某个名词，
而在边界的组合。

这些机制单独看都不陌生，真正的差异是它们被放进了同一个可观察、可限制、可恢复的循环。

06 / Open the hood

想深入时，去看这些文件。

可视化页面讲概念；下面的 Markdown 和源代码负责精确细节。

上下文如何选择？
src/jet/context/attention.py 负责打分和四级呈现；src/jet/context/builder.py 负责 token budget、协议安全的消息分组和最终 prompt。
计划为什么不会拖慢简单任务？
src/jet/context/decompose.py 先用 judge 判断是否需要计划，并与第一步生成并发；计划还有深度、总节点数、去重和可执行性边界。
一次工具调用如何被记录？
src/jet/agent/loop.py 负责执行、持久化和重复调用拒绝；src/jet/policy/permissions.py 负责规则、judge 意见和人工审批。
如何知道 agent 有没有真的完成？
src/jet/agent/verify.py 同时支持 judge 与独立 LLM 验证；结果写入 trace，格式错误或 provider 不可用时明确标记为 inconclusive。
The short version

把完整案例文件留在架子上，每次只递给模型真正需要的几页。

这就是 jet 的核心：持久化状态 + 轻量判断 + 聚焦执行 + 证据验证。便宜的概率性建议，被确定性的代码边界包住。
